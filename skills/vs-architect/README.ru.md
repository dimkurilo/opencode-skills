# vs-architect

🇬🇧 [English version](README.md) · **Русский** · [← все скиллы](../../README.md)

**Разнообразные варианты решения с оценками вероятности — и выход из mode-collapse.**

Реализует Verbalized Sampling ([arXiv 2510.01171](https://arxiv.org/abs/2510.01171)). Вместо того чтобы просить модель дать «тот самый» ответ, вы просите *N разнообразных кандидатов*, каждый с самооценкой вероятности. Сам разброс — это сигнал: узкое распределение значит, что модель уверена, широкое — что стоит разобраться до обязательства.

---

## Когда использовать

- **Выбираете между подходами**, а прямой промпт всё время возвращает один и тот же.
- **Дебаг с неизвестным root cause** — нужны гипотезы, а не первая догадка.
- **Генерация гипотез или синтетических данных** — разнообразие само по себе цель.
- Прямой промпт даёт **повторяющийся, mode-collapsed** ответ.

**Не используйте** для тривиальных скриптов, фактических вопросов («столица Франции») или стабильного продакшен-кода, где один прямой ответ надёжнее.

## Как работает

Прямой промпт → один ответ (что бы ни благоволил prior модели).

**vs-architect** → N вариантов, каждый с:
- своим фреймингом или допущением,
- самооценкой вероятности (`p = 0.X`),
- однострочной причиной этой вероятности.

Варианты сэмплируются **смысленно разными** — не парафразы одной идеи. Вы читаете распределение:

```
Вариант A — p=0.45   «очевидный путь, но сначала проверь X»
Вариант B — p=0.30   «альтернатива, если допущение A не пройдёт»
Вариант C — p=0.18   «длинный выстрел, но дёшево тестировать»
Вариант D — p=0.07   «edge case, игнорировать, если не ...»
```

Если A и B близки — модель не уверена, разбирайтесь. Если A доминирует — коммитьте.

## Когда окупается

- **Архитектурные решения**, где есть 2-3 жизнеспособных дизайна и вы хотите их явно, а не якориться на первом.
- **Root-cause дебаг**, где у бага несколько правдоподобных причин — нужны гипотезы ранжированными, а не один фикс, который может промахнуться.
- **Креатив / стратегия**, где ценность в диапазоне вариантов, а не в среднем.
- **Выход из mode-collapse** — когда модель застряла на повторах, форсирование N разнообразных вариантов рвёт петлю.

## Пример сессии

> **Вы:** Выбираем между Redis, Postgres+LISTEN и managed-очередью для небольшого сервиса async-уведомлений. vs-architect — 4 варианта с вероятностями.
>
> **Агент** *(загружает vs-architect)*: выдаёт 4 разных фрейминга — (A) Postgres+LISTEN p=0.40 (Postgres уже работает, ops-стоимость низкая), (B) managed-очередь p=0.30 (меньше кода, recurring cost), (C) Redis Streams p=0.20 (быстро, новая инфра), (D) poll-the-database p=0.10 (уродливо, ноль новых зависимостей). Каждый с допущением, которое его переворачивает. Вы читаете распределение: A+B вместе = 0.70, значит реальный вопрос «хотим мы это оперировать или платить за это?» — и это вопрос к вам, а не к модели.
